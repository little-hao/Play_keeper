# Play Keeper v2.0.3-rc1 真机验收清单

## 准备

- 备份 VPS 的用户、设备归属、计划状态和计划配置文件。
- 覆盖安装候选 APK，确认账号登录状态和四个 WebView 会话仍保留。
- 部署候选 VPS 到测试目录或测试服务，不直接替换正式服务。
- 确认两台设备在线，八个账号均在当前用户远程页面可见。

## 场景一：缩减有效路线

1. 将 `hao1` 至 `hao5` 标记为当天副本已完成，`hao6`、`hao7` 保持未完成。
2. 保持完整配置路线为 `hao → hao1 → hao2 → hao3 → hao4 → hao5 → hao6 → hao7 → hao`。
3. 在套装实际位于 `hao` 时启动多用户挂机。

预期：

- 控制台显示本轮路线 `hao → hao6 → hao7 → hao`。
- 明确显示已跳过 `hao1`、`hao2`、`hao3`、`hao4`、`hao5`。
- 第一段指定买家为 `hao6`，不再向 `hao1` 发起装备交易。

## 场景二：跨设备连续推进

完整运行 `hao → hao6 → hao7 → hao`，逐段确认：

- 买方取得完整套装后，卖方停止刷新交易所、穿戴剩余装备并返回圣兽云殿。
- 买方完成副本、最终穿戴、背包刷新和道具拍卖后，自动成为下一段卖方。
- `hao7 → hao` 完成后，`hao` 执行匹配金币的道具购买并回到圣兽云殿。
- VPS 不在任何一段长期停留于“买方运行中”或“卖方运行中”。

## 场景三：人工中断与恢复

1. 在任一装备段中断多用户挂机。
2. 展开“人工确认套装所在账号”。
3. 检查 `hao`、`hao1`、`hao2`、`hao3`、`hao4`、`hao5`、`hao6`、`hao7` 均存在；离线账号应显示“离线”。
4. 选择实际持有套装的账号并继续。

预期：

- 不会因当前有效路线较短而缺少后续账号。
- 从所选持有者开始，只连接其后尚未完成副本的账号，最终回到主号。
- 连续中断、恢复两次后，完整配置路线仍未被改写或丢失。

## 场景四：不需要人工确认的正常流程

当装备数量、购买记录和穿戴结果均可自动验证时：

- 不显示“逐步核对主宠装备”阻断页面。
- 自动完成副本与回挂机。
- 只有页面明确冲突、装备不足或证据缺失时才进入人工介入。
