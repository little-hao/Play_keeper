# Play Keeper v2.0.3-rc2 / rc2.1 真机验收清单

## 准备

- 备份生产 VPS 的 `.env`、用户与设备归属、脚本设置、计划状态、计划定时和诊断目录。
- 将 rc2 VPS 部署到测试目录或测试服务，不直接替换生产服务。
- 在手机保留正式版，同时安装“Play Keeper 候选版”；首次为候选版填写测试 VPS 地址和设备密钥。
- 确认候选版与正式版可分别启动，切换候选版设置不会改变正式版远程连接。
- 候选版打开“远程”后点击“使用候选版测试服务器”，确认地址为 `wss://keeper-test.19990920.xyz/device`；填写测试 VPS 的 `DEVICE_TOKEN` 后保存并连接。
- 确认设置页能显示“远程连接已上线”；密钥错误时明确显示“设备密钥被服务器拒绝”，而不是仅显示含义不明的异常按钮。

## 场景一：五件批次中途断网

1. 从 `hao6 → hao7` 启动装备转移。
2. 卖方已有一至四件上架或成交时断开买方设备网络。
3. 等待控制台进入离线或人工介入，不要手工重新上架同名装备。
4. 恢复网络，在控制台选择实际套装所在账号 `hao6` 并继续。

预期：

- 卖方与买方均收到恢复任务。
- 已上架装备由买方继续购买；已经成交的装备不重复购买或上架。
- 买方购买腾出栏位后，卖方继续上架仍在背包中的装备。
- 不因目标装备数少于五件而误报“五件上架限制”。
- 完整套装到达 `hao7` 后继续穿戴、副本、剩余装备穿戴、背包刷新和回圣殿。

## 场景一前置：首棒卖方脱装备

1. 让 `hao` 主宠穿戴完整目标套装，并保证交易所至多存在四件非目标商品。
2. 启动 `hao → hao7 → hao` 多用户挂机。
3. 观察 APP 在进入装备交易所前的一键脱装备与装备栏复核状态。

预期：唯一可识别的十个主宠装备槽确认清空后才进入交易所；若脱下动作未生效则留在宠物资料页重试，绝不能直接进入交易所。

随后单独补测五件非目标商品占满：脱装确认成功后仍应明确提示“主宠装备栏已清空，但五个栏位被其他商品占用”并安全暂停；不得自动下架或覆盖既有商品。

## 场景二：买方持续离线

在部分装备上架后保持 `hao7` 离线。

预期：卖方保留现场并等待，不重复上架、不切换装备所在账号、不自行进入下一棒。买方重新上线并人工继续后恢复同一段。

## 场景三：无关商品占满五栏

在卖方交易所预先放置五件与目标套装无关的商品，再尝试恢复。

预期：系统明确提示无关商品占满交易栏位并暂停；不得自动下架、误卖、切换买方或宣称装备转移完成。

## 场景四：完整收尾

从恢复后的 `hao6 → hao7` 继续到 `hao7 → hao`。

预期：每棒买方完成副本后成为下一棒卖方；前一棒卖方穿戴剩余装备并返回设定挂机地图；最终装备回到 `hao`，主号完成配置的后续购买及挂机步骤。

## 场景五：双版本共存

- 系统设置中同时存在“Play Keeper”和“Play Keeper 候选版”。
- 两者可分别打开，远程地址、设备密钥、账号选择和网页登录状态互不覆盖。
- 卸载候选版不会删除正式版数据；正式版仍可按原配置连接。
