# Play Keeper v2.0.4-rc2 候选版说明

构建日期：2026-10-25。

## 本轮修复

真机路线 `hao → hao3 → hao4 → hao7 → hao` 暴露出一个非必要的等待条件：装备已经完整到达买方，买方也已完成副本、穿戴、背包快照并返回指定挂机地图，但计划仍等待上一卖方产生新的“穿戴完成”时间戳。部分账号在没有剩余装备可调整时不会产生该新时间戳，导致路线停在 hao3 或 hao4，无法自动开始下一段转移。

rc2 将上一卖方的重新穿戴与返回挂机改为后台非阻塞收尾。只有买方完整确认仍是进入下一段的必要条件；上一卖方收尾失败会保留 `seller_cleanup_warning` 诊断，但不会阻塞买方道具拍卖和下一次装备转移。

## 版本与部署边界

- Candidate APK：`com.local.sgplaykeeper.candidate`，versionCode 52，versionName `2.0.4-rc2-candidate`。
- VPS：`2.0.4-rc2`。
- 本版为并行安装候选版，不覆盖 v2.0.3 正式 APP。
- 必须同步更新测试 VPS 与 Candidate APK；不应将 rc2 直接替换生产环境。
- 更新 VPS 时保留 `.env`、用户和设备归属、计划状态、单次转移状态、邮件配置及诊断目录。

## 验证结果

- VPS Node 测试：59/59。
- 新增自定义闭环回归：卖方无新收尾时间戳仍自动进入 `hao3 → hao4`；卖方收尾命令失败只记录警告。
- Android：使用 Java 17、SDK 35、Build Tools 35.0.0 构建 Candidate。

自动测试不执行真实游戏交易。安装后仍需用上述五账号闭环复测完整成交、各小号副本和最终 hao 返回指定挂机副本。
