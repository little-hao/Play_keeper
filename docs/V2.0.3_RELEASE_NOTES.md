# Play Keeper v2.0.3 正式构建说明

构建日期：2026-10-23。Android versionName `2.0.3`，versionCode `50`；VPS `2.0.3`。
“正式构建”表示版本标识与本地制品完成，不代表已自动替换生产 VPS。

## 本次修复

- `hao → hao7 → hao` 最后一段完成后，hao 的组合道具购买最多等待60秒。未成功时服务端下发中断、恢复该账号挂机设置并启动挂机；计划以“购买已跳过”完成，不再无限停留在交易所。
- 保留购买立即成功的原流程，也保留明确购买错误时的人工介入。超时策略只处理“一直运行但未完成”的情况，不把交易结果伪装为购买成功。
- 多用户挂机默认提供完整八账号循环；当天已完成副本的中间账号仍由既有逻辑自动跳过。

## 启动前可配置项

- 装备转移循环和装备套装。
- 装备定向转移价格，默认920金币。
- 道具组合及道具拍卖/购买价格，默认920金币。
- 副本组合、统一背包检查项目。
- 默认挂机副本及每个账号各自返回的挂机副本，默认圣兽云殿。

输入留空时使用上述默认配置。保存后仍按当前网页登录用户独立持久化，旧版保存数据会自动补齐新增字段。

## 验证与发布边界

- VPS 自动测试覆盖完整路线、缩短路线、断点恢复、跨设备推进、60秒购买超时、独立价格及逐账号挂机副本。
- Android 正式包完成编译、lint vital、29项单元测试、包名/版本及v2签名验证。
- 正式 APK 使用原正式包名和签名，可覆盖安装；候选版包名不同，仍可并存。
- VPS 包不包含 `.env`、运行数据、用户密码、Device Token、`node_modules` 或签名密钥。

## 部署建议

1. 停止新计划并确认套装实际所在账号。
2. 备份 VPS 的 `.env`、用户/设备归属、计划状态、计划设置及诊断文件。
3. 更新 VPS 后先确认 `/health` 返回 `2.0.3`，再覆盖安装正式 APK；不要卸载 APP。
4. 先复测 `hao → hao7 → hao`：成功购买应正常完成；持续未购买应在约60秒后返回设定挂机副本。
5. 再使用完整默认循环，确认各账号独立挂机副本和两类价格均生效。

若出现重复交易、装备位置不明或错误账号购买，应立即中断并保留现场，不要在未确认套装账号时连续重试。
