## 1. 本版范围

- 修复装备部分上架、部分成交或买方掉线后的恢复流程。
- 恢复时同时启动卖方与买方，同设备账号会传递卖方账号索引并建立联动。
- 交易所栏位计算包含所有有效商品，不再只计算本轮目标装备。
- 五个栏位含本轮目标装备时先让买方购买并腾出栏位；五个栏位均为无关商品时安全暂停。
- 新增独立 `candidate` 构建，可与正式版同时安装并分别保存远程连接和 WebView 会话。

主要实现文件：

- `app/src/main/java/com/local/sgplaykeeper/AutomationCoordinator.java`
- `app/src/main/java/com/local/sgplaykeeper/EquipmentListingReconciler.java`
- `app/src/main/java/com/local/sgplaykeeper/MainActivity.java`
- `remote-server/eight-account-plan.js`
- `remote-server/server.js`

## 6. Mac 构建环境

安装 JDK 17、Android SDK Platform 35、Build Tools 35.0.0 和 Node.js 20 或更高版本。设置：

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/build-tools/35.0.0:$PATH"
printf 'sdk.dir=%s\n' "$ANDROID_HOME" > local.properties
java -version
node --version
```

仓库中的 `gradlew` 已保存可执行权限；若文件由非 Git 方式传输导致权限丢失，再执行 `chmod +x gradlew`。

## 8. 签名连续性

`candidate` 会优先使用未纳入 Git 的 `signing/debug.keystore`，其次使用 `$HOME/.android/debug.keystore`。若 Mac 使用新生成的 Debug 密钥，包名仍可与正式版共存，但不能覆盖安装 Windows 已签名的 rc2 Candidate。

需要在两台平台间覆盖安装同一 Candidate 时，应通过加密渠道复制原保留 keystore，并在放入 `signing/debug.keystore` 前核对：

- keystore SHA-256：`bc351381ba0cf1846cad1408373a7b55f6f757f400d941ba3f9edacb14799c9f`
- 证书 SHA-256：`11e8c49415512da2ce088b92b1c2161a960744bcb5829507bcd0021fb3cf512f`

不得通过 GitHub、普通聊天、VPS 包或公开 Release 传输 keystore。签名资料的既有管理说明见 `MAC_RELEASE_HANDOFF_V2.md`。

本次私有交接应使用工作区外的 AES 加密 7z 包，开启文件名加密，并通过独立渠道传递解压密码。Mac 解压后先核对 keystore SHA-256，再把它放到仓库的 `signing/debug.keystore`；该路径已被 Git 忽略。使用完成后，保留在加密存储中，不要把解压后的裸密钥长期放在下载目录。

## 9. 双版本开发边界

- 正式版：`com.local.sgplaykeeper.test.v190`。
- 候选版：`com.local.sgplaykeeper.candidate`。
- 两者的 SharedPreferences、WebView 数据、远程地址、设备密钥和游戏登录会话互不共享。
- Candidate 首次安装需要单独配置一次测试 VPS；之后无需修改正式版连接。
- Mac 继续测试 rc2 时使用 `assembleCandidate`，不要把 `assembleRelease` 产物当作并行测试包。
