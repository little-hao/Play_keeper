# Play Keeper v2.0.2 正式构建说明

构建日期：2026-10-21。Android versionName=2.0.2，versionCode=45。
本文件所称“正式构建”是版本标识与制品状态，不表示已经替换生产 VPS。

## 用户验收结论

用户已完成 hao → hao2 → hao 的缩短路线测试。两次人工确认后，装备穿戴、副本、剩余装备穿戴及返回圣兽云殿均能走完。该结果证明人工兜底链路有效，同时暴露两个正式版前补丁：正常流程不应强制确认；跨设备最终主号可能因双方上报先后次序而不执行道具购买。

## 正式版改动

- 装备购买记录完整、没有跳过项目，并且穿戴后的已填充装备槽数量达到目标套装件数时自动继续。仍保留两类人工确认：装备槽数量不足；网页能证明主宠身份但读取到的名称与目标清单冲突。
- 多用户计划分别记录买方流程完成和卖方收尾完成；两者无论谁最后上报，都会进入小号道具拍卖或最终主号购买。不会要求已经空闲的另一台设备再发一帧状态。
- 展示页按当前登录用户收到的设备和账号汇总所有 `inventoryCounts`：同名道具相加，展示账号数量及每类总数；各账号原始明细继续保留。服务端原有用户/设备隔离决定可见范围。
- rc7 的任务代次隔离、断线/超时保护、重启暂停、人工确认令牌、单次转移面板和诊断下载全部保留。

## 自动验证

- 服务端包含缩短路线的跨设备乱序用例：主号完成后不再上报，卖方稍后完成，系统只发送一次 `run_auction_buy` 给 hao。
- Android 增加工作流验收用例：完整购买+空跳过清单+足够槽位可自动继续；缺件、跳过或槽位不足不能继续。
- 浏览器测试使用两个账号和三类物资，验证汇总为进化宝石 7、曙光印记 3、强化丹A 4，并继续检查手机/桌面无横向溢出。

正式制品的文件名、SHA-256、版本和签名信息见 `V2.0.2_BUILD_MANIFEST.md`。

## 部署与回滚

1. 停止新的多用户计划，记录套装实际所在账号；备份 `.env`、用户/设备归属、计划设置、计划状态、诊断和新增的 `.transfer` 状态文件。
2. 更新 VPS 程序并安装锁文件依赖，保留数据目录；再覆盖安装 APK。不得卸载 APP，以免丢失 WebView 会话与本地设置。
3. 先用 hao → hao2 → hao 验证自动继续、hao2 道具拍卖、hao 最终购买及背包合计，再恢复完整八账号路线。
4. 若出现错误交易、串用户、重复购买或套装位置不明，立即中断计划并保留现场；不要在未确认装备所在账号时反复点击恢复。
5. 回滚前也需先停止任务和确认装备现场。Android 不保证可直接降级安装；需要回退时应生成使用相同签名、versionCode 更高的回滚构建，不能通过卸载绕过。

## 仍建议的后续补丁

- 高优先级：为每个跨设备业务步骤加入服务端生成的 stepId，并由 APP 在真正完成时持久回执，逐步替代时间戳推断。
- 高优先级：收集实际游戏 DOM 样本，增加稳定的主宠和装备名称读取；目前“无报错自动继续”是工作流证据，不是逐件名称的机器证明。
- 中优先级：真实八账号完整循环、VPS 重启、断网恢复及 iPhone Safari 长时间预览回归。
- 中优先级：默认密码、浏览器保存密码与 device_token 的生产安全迁移；不在本次兼容发布中静默改变。
- 低优先级：处理 Android lint 的依赖、图标与硬编码中文警告，并逐步拆分体量较大的自动化协调类。
