## 已实现

- Android 按账号隔离延迟任务及网页回调；取消、完成、开始新运行均更新执行代次。
- 不再把目标清单填充为实际穿戴证据。实际名称、槽位、主宠身份不能可靠确认时停在人工核验。
- 人工确认携带一次性运行令牌；中断、结束或装备配置变化后拒绝旧确认。
- 修复当天已完成副本时，最终穿戴/背包收尾的任务阶段标识。
- 单次装备转移保存运行状态，断线/拒绝/超时停下两方；重启后等待处理，不自动重放交易。
- 重复买方回报只触发一次卖方收尾；返回挂机还需本轮穿戴完成记录。
- 控制台集中显示待核验、单次转移、请求/回执/失败；高风险进程入口仍保留，移至折叠区。
- 新增恢复、异常及网页读取测试；CI 增加 PR/codex 分支入口、服务端测试、Android 静态检查与测试报告。

## 必须诚实保留的限制

1. 网页实际是否提供 data-pet-scope/main、data-main-pet 或装备名称属性，尚无真机证据。当前适配器是保守的：缺少主宠身份即暂停，可能每次转移都需要人工确认。不能把此版本称为已完成全自动装备识别。
2. 执行代次阻止旧回调继续推进，不能撤回已发送到网页或服务器的点击/交易。
3. APP 与 VPS 的业务完成证据仍有时间戳依赖；端到端 runId/stepId 回执协议及持久化指令队列留作后续设计，不宣称 exactly-once。
4. 未改变存仓失败策略、账号并发产品策略、默认密码/浏览器记住密码策略。生产安全整改应另做迁移方案。
5. 界面主要解决反馈和待处理入口，未全面重做原生 APP 布局；真实滑动、低端设备性能、长时间后台及 Safari 仍待测试。

## 用户真机验收顺序（未执行）

先在测试设备/独立 VPS 环境使用，不直接替换生产；备份用户、设备归属、计划设置、计划状态与新增 .transfer 状态。

1. 覆盖安装：检查原登录状态、账号、设备分配和每用户设置是否保留。不得卸载旧包来绕过签名问题。
2. 单次跨设备：选小范围目标装备，确认五件分批；核验不足时不自动进入副本。取消确认不继续，确认后进入副本。
3. 卖方收尾：买方确认套装后，卖方停止交易所刷新、穿戴剩余装备、返回配置地图。记录两方画面与阶段时间。
4. 完整循环：hao→hao1→hao2→hao3→hao4→hao5→hao6→hao7→hao；测试中断后选 hao3 继续，第二次中断、重连后再次继续；检查完整路线不被裁断。
5. 异常：断网、设备离线、APP 拒绝、VPS 重启、重复点击确认。不得自动重复购买或把旧确认用于新任务。
6. 已完成副本：同一天重入应跳过重复副本，但完成剩余穿戴、背包统计和回挂机。
7. 多用户：霜冻前夜仅看到自己设备的四账号、配置和待处理事项；hao 原设置不变。
8. 保留签到/日常任务、价格自定义、套装编辑、仓库/威望开关、截图滑动、诊断下载、定时和报告回归。

## 每次反馈格式

- APK 与 VPS 版本、校验值、设备型号/Android/WebView/浏览器版本；
- 运行编号、完整路线、当前转移段、卖买双方设备、实际套装所在账号；
- 期望行为、实际行为、首次异常时间、是否执行过人工确认；
- 下载的本用户报错说明、两方截图、脱敏日志；不要上传密码或 device_token；
- 严重程度：错误交易/串用户为阻断；无法继续为高；文案布局为一般；
- 修复版本与复测结果。未复测保持“待验收”，不能因构建成功关闭问题。

只有上述关键场景由用户确认后，才讨论部署与正式版。回滚必须先停止任务并核对装备现场；旧版可能不允许直接降级安装，需单独安排可升级的回滚包，不清除用户数据。
