# Play Keeper 2.0.8-rc1 覆盖升级与八账号验收

本候选版使用正式版包名和原签名覆盖2.0.7。安装前应保留现有APK及必要的设备备份，不要卸载旧版；卸载会清除WebView登录资料。

## 升级保护

1. 覆盖安装后，账号1–4应保持原名称、登录状态、最后页面和脚本设置。
2. 默认仍显示4个账号，标准模式默认开启，不自动创建或加载账号5–8。
3. 在APP顶部点击“账号”，把配置数量改为8。账号5–8使用新的独立WebView Profile。
4. 依次打开账号5–8并登录。未打开的Profile在VPS上不得被视为在线可执行账号。

## 标准模式

1. 保持高性能模式关闭，确认APP和VPS均显示并发容量4。
2. 依次切换八个账号，确认绿色实心圆表示已加载、空心圆表示休眠；休眠后重新打开仍保持登录状态。
3. 选择八账号每日任务。第一批只允许4个账号运行，第一批全部完成证据、背包快照及返回挂机后，才启动第二批。
4. 任务期间切换账号、远程预览和中断不得把任务发给错误Profile。

## 高性能模式

1. 在“账号”设置中勾选高性能模式并保存，确认VPS显示“高性能8账号”。
2. 启动八账号每日任务，确认八个账号可同时接收命令。
3. 观察至少2小时的可用内存、设备温度、网页加载时间、远程重连和渲染进程退出次数。
4. 同一账号的网页进程在10分钟内连续退出两次时，APP应自动退回标准4账号模式。

## 同IP验证

APP不会尝试绕过站点限制。若第5–8账号出现登录拒绝、被挤下线或返回登录页，应保留远程状态、失败步骤和截图，并与APP低内存或WebView进程退出区分。

## 发布门槛

- VPS自动化测试全部通过。
- GitHub Actions完成Android单元测试、Lint和release覆盖包构建。
- 原四账号覆盖升级无数据丢失。
- 标准模式八账号两批完整运行通过。
- 高性能模式结果仅作为真机能力结论，不因单台设备不支持而绕过安全回退。

本版本最多配置8个账号，不包含9个及以上账号的开发或验证。
