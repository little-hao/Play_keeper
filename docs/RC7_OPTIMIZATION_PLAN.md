# v2.0.2-rc7 兼容性优化与验收计划

基线：`187b66a` / v2.0.2-rc6。用户已确认以下边界：

- 保留所有既有功能、包名、签名、账号 Profile、设备归属及用户配置。
- 无法可靠核验目标装备时暂停，允许人工确认后继续。
- 允许重新分组界面，保留操作入口和可编辑设置。
- 仅交付候选版；不部署生产 VPS，不执行真实交易。

## 本轮顺序

1. 建立原有自动测试基线及可复现的问题用例。
2. APP：隔离旧回调，使用实际观察结果验收，提供明确的人工确认入口。
3. VPS：强化手动转移的异常处理及协调边界，测试反复恢复。
4. 控制台：就地反馈、人工确认、配置与操作分组、手机适配。
5. 补齐 CI 与候选版验收说明，生成可用的本地候选制品。

## 必须保持

- 装备精确名称与强化后缀匹配，九件/十件/自定义套装。
- 五件分批、买家与价格复核、完整路线及每日副本跳过规则。
- 签到、日常任务、存仓策略、威望开关、资源归集、报告邮件。
- 用户隔离、设备分配、重连、远程预览与滑动。
- 本地与远程已有单账号操作、取消、人工恢复与诊断下载。

不在本轮改变：默认密码策略、存仓失败继续策略、账号并发产品策略、网站操作方式及正式签名。相关改动需单独设计迁移或再次确认。

## 验收要点

- 相同账号、相同任务类型的新运行不能被旧回调修改。
- 不能把预期装备清单当作实际穿戴结果；证据不充分时暂停，人工确认仅作用于当前运行。
- 重复中断/恢复及持久化重建后，完整路线保持不变。
- 手动交易与每日计划不能同时控制同一执行资源。
- 请求发送、接受、执行结果不能混为一种“成功”。
- 断线、拒绝、超时有可见原因，不能无期限显示运行中。
- 所有原有自动测试继续通过；新增异常路径测试。
- 真机八账号闭环、装备实际读取与人工确认、覆盖升级需用户验收，不以模拟测试代替。
