# Play Keeper 远程中继服务

## v2.0.3 正式版增量

- 最终主号组合道具购买增加60秒上限；未成交时取消购买并执行返回挂机，不再无限刷新交易所。
- 多用户挂机配置增加完整八账号默认循环、装备价格、道具价格和逐账号挂机副本；旧配置会自动补齐默认值。
- VPS 健康检查版本为 `2.0.3`。部署时保留现有 `.env`、用户/设备归属、计划状态与诊断文件。

## v2.0.3-rc2 候选版增量

装备转移恢复会同时启动卖方和买方，并把同设备的账号索引传给 APP。APP 会先复核卖方背包、目标装备的有效上架记录及交易所全部占用栏位，再决定继续上架、等待买方或安全暂停。五个栏位已满但其中存在目标装备时，不再误报“五件上架限制”，而是由买方购买后让卖方继续补齐。

本版配套 Android 候选包使用独立包名 `com.local.sgplaykeeper.candidate`，可以和正式 APP 共存，候选版远程连接配置不会覆盖正式版。候选 VPS 仍应部署到测试服务或测试目录；不要直接替换生产服务，真机验收要求见 `docs/V2.0.3_RC2_ACCEPTANCE.md`。

## v2.0.3-rc1 候选版增量

服务端会保留完整配置路线，并根据账号当日副本完成状态生成本轮有效路线；已完成账号从装备接力中跳过，但当前装备持有者和最终主号不会被删除。人工恢复下拉框仍使用完整路线，支持从任意在线账号继续。

跨设备完成判断使用各账号启动前状态作为基线，不要求手机和 VPS 绝对时间完全一致。控制台会显示有效路线与跳过账号。本版尚待真机完整闭环确认，不应直接替换正式生产版本。

## v2.0.2 正式构建增量

当前源码为 `2.0.2`，包含 rc7 验证过的可靠性改动。新增单次转移持久化文件
`<PLAN_STATE_FILE>.transfer`；升级、备份、回滚时应与原计划状态一起保留。
运行中的单次转移在服务重启后只恢复为待处理，不自动重放交易。
控制台保留异常时的人工装备核验入口；无错误且穿戴数量完整时配套正式 APP 会自动继续。
本轮仅生成正式制品，未部署生产。发布说明见 `docs/V2.0.2_RELEASE_NOTES.md`（源码仓库）。

该目录提供 v2.0.2-rc6 的远程连接服务和适配手机/电脑浏览器的响应式控制台。安卓 APP 主动建立加密 WebSocket 连接，因此不需要手机公网 IP，也不需要在 Android 上开放入站端口。生产服务示例把计划状态、用户、设备归属、脚本设置和各用户独立的多用户挂机报错说明保存在 `/var/lib/play-keeper/`，升级程序目录不会清除数据。服务重启或人工介入后可选择套装实际所在账号，并从该账号开始按原装备循环的剩余顺序继续。单次装备定向转移也由 VPS 跟踪跨设备买卖，套装到达买方后自动释放卖方并返回挂机。

管理员手动分配的设备归属优先级高于令牌自动认领，APP 重连不会覆盖手动设置。旧版 `data/users.json`、`plan-state.json` 与 `plan-schedule.json` 部署升级前应复制到 `/var/lib/play-keeper/`，文件所有者设为 `playkeeper`。

设备上报账号后，服务会按该普通用户当前分配的全部设备汇总并保存账号清单。旧设置或旧路线中属于其他用户的账号会被移除；同一浏览器切换用户时也会先清空上一用户的设备、计划和账号选项。

首次启动会创建管理员 `hao管理员`、普通用户 `hao` 和 `霜冻前夜`，初始密码均为 `20261016`。登录页可同时输入用户名、密码与 `device_token`；未绑定的用户会在首次成功登录时绑定该 token，之后设备使用相同 token 上线即归属该用户。请在完成部署与验证后及时修改默认密码。

## 本地启动

要求 Node.js 20 或更高版本：

```bash
npm install
ADMIN_TOKEN='生成一个至少16位的管理密钥' \
DEVICE_TOKEN='生成另一个至少16位的设备密钥' \
node server.js
```

完成报告邮件为可选功能。生产环境增加以下变量后，挂机脚本完成时会发送逐账号及合计背包报告；邮箱密码必须使用邮件服务提供商生成的应用专用密码，不要写入仓库：

```bash
SMTP_HOST='smtp.gmail.com'
SMTP_PORT='465'
SMTP_SECURE='true'
SMTP_USER='发件邮箱'
SMTP_PASS='应用专用密码'
REPORT_FROM='发件邮箱'
```

收件地址由网页启动挂机脚本时填写，默认留空。未配置 SMTP 时流程仍会完成，并在页面明确显示邮件未发送。

浏览器打开 `http://127.0.0.1:8080`。生产环境必须通过 HTTPS/WSS 使用，示例 `Caddyfile.example` 会自动申请证书并反向代理到本服务。

## 手机上填写

- WSS 地址：`wss://keeper.example.com/device`
- 设备密钥：服务器环境变量 `DEVICE_TOKEN`
- 首位管理员：用户名留空，密码填写服务器环境变量 `ADMIN_TOKEN`
- 普通用户：由管理员在控制台创建用户名和密码，并分配可管理设备

管理密钥和设备密钥必须不同。网页管理密钥仅保存在 Safari 的 `sessionStorage`，关闭标签页即清除；安卓设备密钥使用 Android Keystore 加密保存。

## 安全边界

- 只允许固定的 APP 内命令，不支持任意网址、脚本、系统命令或整机远控。
- 设备与控制台分别鉴权；管理端每分钟最多发送 180 条命令，以支持受控单击。
- 中继实时状态只保存在内存；账号的每日装备、副本时间与背包快照由 Android 端持久化，服务重启后由设备重新上报。
- v0.5 只传输 Play Keeper 自有 WebView 的按需压缩截图，不使用整机录屏。
- 截图只在内存中转发，不写入磁盘；单帧解码大小最多 2.5 MiB。
- 预览可选 720/1280/2560 三档，高分辨率会自动降低刷新频率。
- HTML `select` 的 Android 原生弹窗不进入截图；Relay 会转发经过裁剪校验的选项列表，并接受白名单 `select_option` 命令。
- 竖屏和横屏帧都按实际宽高比用 `contain` 完整显示，控制台不裁切手机页面。
- 控制台可按当前账号配置/立即执行定时拍卖、12h金币券商店卖出、每10分钟多道具存仓、圣兽云殿守护、自选副本队列和威望道具使用；账号战斗统计连续30分钟不增加时显示红色“掉线”。VPS 只转发白名单参数，不保存脚本配置。
- 装备定向转移限制1–10个精确装备名和指定单价，卖方首批最多上架5件，20秒后自动启动同一 APP 内用户名匹配的买方账号；成交后卖方重进交易所继续后5件，外部买方不在本设备时使用60秒宽限结束等待。
- 控制台支持双设备八账号完整接力 `hao → hao1 → … → hao7 → hao`，可保存每日定时运行时间；今日副本已完成的中间账号会被跳过。中断后必须人工确认厄菲斯神套装所在账号，再从该卖方继续。页面顶部统一配置背包检查项目，并汇总每个账号今日装备转移、副本完成、背包物资快照与最近异常现场留存状态。
- “退出 KeepPlayer”只将任务退出前台并保留 WSS 连接，以便“启动 KeepPlayer”仍能把同一任务切回前台；进程被系统强制停止后无法远程自启动。
- 道具拍卖卖方保留1个、单次最多5条；买方可扫描购买全部配置单价（默认920）的可见记录。
- 全背包存仓可立即、定时或在圣兽云殿/每个副本开始前执行；选择器同时兼容桌面与手机挂机辅助页。
- 远程画面支持单击、拖动滑动及上下左右快捷滑动；不支持键盘输入或控制其他 APP。
- Android 14 的整机屏幕捕获每个会话仍需用户授权，不适合无人值守挂机。
