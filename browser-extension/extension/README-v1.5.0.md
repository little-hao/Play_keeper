# Play Keeper v1.5.0

## 1. 本版修复

诊断日志显示第一周期经历多次可验证的合成失败后成功完成。下一周期新生成的同名主宠已正确读取为“鬼精灵欧姆 Lv1、CC 55.3、进化 0”，但旧版在随后的第二次核验中重新带入合成前的 CC/进化字段，最终误报“选中后属性资料未稳定加载”。

本版选择同名新主宠时：

- 使用名称、唯一卡片和卡片实时等级确认身份。
- CC、进化次数及经验状态一律从当前属性页重新读取。
- 名称或卡片不唯一时仍保持安全暂停。

## 2. 自动循环运行统计

每次自动循环结束时，运行提示框会显示：

- 启动和完成的周期数。
- 在牧场补级的副宠数量。
- 在携带栏补级的主宠和副宠数量。
- 实际取出的副宠数量。
- 进化尝试、成功及材料不足跳过次数。
- 合成提交、成功和失败次数。
- 本轮总耗时和中断原因。

统计同时写入诊断事件 `automation/run-summary`。正常的合成失败重试会计入“合成失败”，但不会误记为流程异常；只有最终无法继续时才增加错误次数。

## 3. 短期签名许可证

扩展新增：

- `license-config.js`：授权开关、服务器地址、产品标识及验证公钥。
- `license-client.js`：激活、签名验证、续签、有限离线使用和最低版本检查。
- 规划器许可证区域：输入激活码、检查续签和清除当前许可证。

配套服务器位于扩展目录外的 `PlayKeeper-License-Server-v1.5.0`。服务器保存私钥和激活码清单，扩展 ZIP 不包含私钥。

### 默认状态

`license-config.js` 默认 `enabled: false`，用于当前调试，避免服务器尚未部署时阻断游戏流程。此状态不具备防传播效果。

### 本地启用

1. 启动 `PlayKeeper-License-Server-v1.5.0/start-license-server.ps1`。
2. 将扩展 `license-config.js` 的 `enabled` 改为 `true`。
3. 重新加载扩展。
4. 输入服务器 `server-config.json` 中的激活码。

### 正式启用

1. 在 HTTPS 域名部署授权服务器。
2. 重新生成 P-256 密钥对。
3. 私钥只放服务器；公钥填入扩展 `license-config.js`。
4. 将 `serverBaseUrl` 改成正式 HTTPS 地址。
5. 在 `manifest.json` 的 `host_permissions` 加入该授权域名。
6. 把 `enabled` 改为 `true` 后重新打包扩展。

不要把授权服务器目录、私钥、激活码清单或 `license-state.json` 发给插件用户。

## 4. 保留行为

- 单只牧场副宠从当前等级到 Lv40 使用一份固定经验组合，达到 Lv40 后才为下一只重新规划。
- 强化丹 A/B 均不足时，自动循环跳过剩余进化并进入合成。
- 合成失败继续等待冷却、恢复选择并在上限内重试。
- 保留 v1.2.5 累计经验修复、唯一匹配保护和诊断日志。
